# 테라폼 인프라 / Terraform Infrastructure

## 역할 / Role
v2 전체 인프라의 단일 Terraform 루트 — `v2/foundation/` 하나로 엣지/인증/Aurora/ECS/AgentCore/워커를 관리.
partial S3 backend(`backend.hcl`) + count/flag 게이트 방식.
(Single Terraform root for all v2 infra. Partial S3 backend + count/flag gating.)

## 주요 파일 / Key Files (`v2/foundation/`)
- `backend.hcl` — partial backend 값(bucket/key/use_lockfile). gitignored, `make configure`가 생성. init은 반드시 `terraform init -backend-config=backend.hcl` (Partial backend config; gitignored, generated by `make configure`)
- `staging.tfvars` — **`admin_email`/`admin_password` 평문 포함. gitignore에 없고 untracked — 절대 커밋 금지** (`git add -A` 주의) (Contains plaintext admin password; NOT gitignored — never commit)
- `backend.hcl.example` / `terraform.tfvars.example` — 커밋 가능한 템플릿 (committable templates)
- `variables.tf` — 대부분의 플래그 선언. 단 `agentcore_enabled`/`integrations_enabled`는 **`ai.tf` 상단에 선언** (Most flags here, but agentcore/integrations flags are declared in `ai.tf`)
- `migrations/*.sql` — DB 마이그레이션. terraform이 아니라 `make migrate`(scripts/v2)가 적용. 베이스라인은 `data/schema.sql`(v9 동결) — 스키마 변경은 항상 새 마이그레이션 파일로 (Applied by `make migrate`, not terraform; schema changes go in new migration files)
- 도메인별 `*.tf`(edge/auth/data/workload/ai/workers/eks/steampipe 등) — 루트 CLAUDE.md "주요 파일" 참조 (per-domain files; see root CLAUDE.md)

## 플래그 게이트 / Flag Gates
- 대형 기능은 전부 flag 게이트, **기본 false** → `plan`=No changes, $0: `agentcore_enabled`, `integrations_enabled`, `steampipe_enabled`, `workers_enabled` 외 다수 (All large features flag-gated, default false)
- 파생 플래그는 validation으로 의존 플래그 강제 (예: `datasource_diagnosis_enabled` → workers+agentcore+integrations) (Dependent flags enforced via validation blocks)
- `remediation_enabled`/`integrations_write_enabled`는 **ADR-005 FROZEN — 활성화 금지** (FROZEN, do-not-enable)

## 규칙 / Rules
- **공유 인프라에 `-auto-approve` 금지** — `plan -out tfplan` 후 컨트롤러가 `apply tfplan` (No -auto-approve; saved-plan apply by controller)
- **SG `description` 불변** — 변경 시 ALB 의존성으로 replace hang. ingress는 in-place로 (SG description immutable)
- **IAM inline 정책 긴급 수정 관례**: `aws iam put-role-policy`로 즉시 적용하되 **정책 이름/문서를 terraform 코드와 동일하게** 맞춘다 → 다음 apply가 무충돌 수렴(put은 멱등). 코드 반영 없는 put 단독 금지 (Emergency IAM fix: put-role-policy immediately with the SAME name/document as terraform so the next apply converges; never put without the matching code change)
- 이미지 참조는 전부 arm64 (all images arm64)
