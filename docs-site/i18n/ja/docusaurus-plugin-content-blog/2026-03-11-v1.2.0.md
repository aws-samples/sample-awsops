## Gateway 分離: Infra → Network + Container

v1.1.0 の Infra Gateway(41 ツール)はツールが多すぎたため、ネットワークとコンテナのドメインに分離しました。

<GatewaySplitFlow />

| 項目 | Before (Infra 単一) | After (分離) |
|------|---------------------|-------------|
| Gateway | 1 (Infra, 41 ツール) | 2 (Network 17 + Container 24) |
| Container 応答時間 | ~50 秒 | ~23 秒 (**54% 改善**) |
| ツール選択精度 | LLM が 41 個から選択 | 24 個から選択 |
| ルート体系 | 7 Gateway, 9 Routes | **8 Gateway, 10 Routes** |

:::info なぜ分離が効果的なのか?
LLM が 41 個のツール説明をすべて読んで選択するよりも、17 個(Network)または 24 個(Container)の中から選択する方が**より速く、より正確**です。特に Container の質問でネットワークツールを誤って選択するエラーがなくなりました。
:::

デプロイスクリプトにエラーハンドリングと自動検出ロジックを追加しました。

## 主要なバグ修正

| 課題 | 原因 | 修正 |
|------|------|------|
| EKS access entry 失敗 | `arn:aws:sts::` 形式を使用 | `arn:aws:iam::` 形式へ変換 |
| Cognito custom domain エラー | `SupportedIdentityProviders` の欠落 | パラメータを追加 |
| AgentCore 権限エラー | 権限不足 | `bedrock-agentcore:*` 権限を追加 |
| K8s PVC 照会失敗 | JSONB シリアライズエラー | `k8s.ts` で `::text` キャストを適用 |

:::warning Steampipe JSONB の注意
Kubernetes テーブルの JSONB カラム(`spec`、`status`)を直接返すとシリアライズエラーが発生します。
`SELECT spec::text` または `spec->>'key'` に変換する必要があります。
:::
