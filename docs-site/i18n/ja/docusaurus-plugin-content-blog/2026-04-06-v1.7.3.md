### 3 種エクスポート

**DOCX** — `docx` パッケージベースの A4 プロフェッショナルレポート:
- 表紙（タイトル、ヘルススコア、アカウントエイリアス、日付）
- 目次（ハイパーリンク、Heading 1-3）
- セクション別アクセントカラー（コスト=緑、セキュリティ=赤、ネットワーク/EKS=紫、アイドル/MSK=オレンジ）
- マークダウン解析（見出し、テーブル、リスト、引用、インラインコード/ボールド/イタリック）

**Markdown** — すべてのセクションを 1 つの `.md` ファイルにまとめてエクスポートします。

**PDF** — `/ai-diagnosis/report` 専用印刷ページ:
- 白背景の A4 レイアウト、CSS `@media print` によるページ区切り
- 「印刷 / PDF 保存」ボタンでブラウザの Print-to-PDF

```typescript
// src/lib/report-docx.ts (主要な構造)
const doc = new Document({
  sections: [
    coverPage(title, healthScore, accountAlias, date),
    tableOfContents(),
    ...sections.map(s => sectionPage(s, accentColor)),
  ],
});
const buffer = await Packer.toBuffer(doc);
```

| 項目 | 説明 |
|------|------|
| 頻度 | 週次 / 隔週 / 月次 |

type Schedule = {
  enabled: boolean;
  frequency: 'weekly' | 'biweekly' | 'monthly';

UI でトグルの ON/OFF、頻度/曜日/時刻/言語を設定すると、自動的にレポートが生成され S3 にアップロードされます。

:::info S3 アップロード
DOCX と Markdown ファイルは `awsops-deploy-{accountId}/reports/` パスに自動アップロードされます。7 日間有効な Presigned URL を通じてダウンロードできます。CDK スタックに S3 PutObject/GetObject 権限が自動追加されます。
:::

## 6 種の Auto-Collect エージェント

AI 総合診断レポートのデータ収集を自動化する専用エージェントです。各エージェントはマルチソースから並列にデータを収集し、ライブステータスをストリーミングします。

| エージェント | ソース | 収集項目 |
|----------|------|-----------|
| **EKS Optimize** | Prometheus + K8s + Steampipe | CPU/メモリ使用率、スロットリング、Pod 再起動、HTTP 5xx、ノード使用率 |
| **DB Optimize** | Steampipe + CloudWatch | RDS/ElastiCache/OpenSearch のインスタンス発見 + メトリクスベースのライトサイジング |
| **MSK Optimize** | Steampipe + CloudWatch + Prometheus | ブローカーメトリクス、メッセージスループット、コンシューマーラグ、パーティション数 |
| **Idle Scan** | Steampipe | 未アタッチ EBS、gp2 ボリューム、未使用 EIP、停止中 EC2、90 日超のスナップショット、未使用 SG + コスト見積もり |
| **Trace Analyze** | Tempo/Jaeger + Prometheus | サービス別エラートレース、500ms 超のスロートレース |
| **Incident** | CloudWatch + K8s + Prometheus | ALARM 状態のアラーム、Warning イベント、HTTP 5xx の急増、CPU スパイク、メモリ圧迫 |

```typescript
// src/lib/collectors/types.ts
export interface Collector {
  collect(send: SendFn, accountId?: string, isEn?: boolean): Promise<CollectorResult>;
  formatContext(data: CollectorResult): string;
  analysisPrompt: string;
  displayName: string;
}
```

:::tip Collector パターン
すべてのエージェントが同じ `Collector` インターフェースを実装します。`collect()` は `Promise.allSettled` でマルチソースを並列収集し、`SendFn` コールバックで進行状況をリアルタイムに伝達します。新しいエージェントを追加する際は、このインターフェースを実装するだけで済みます。
:::

## FinOps MCP Lambda

Cost Gateway に **5 つの FinOps ツール**が追加されました。

| ツール | ソース | 説明 |
|------|------|------|
| `get_rightsizing_recommendations` | Compute Optimizer | EC2/RDS/ECS/Lambda のライトサイジング + 月間削減額 |
| `get_savings_plans_recommendations` | Cost Explorer | Savings Plans の購入推奨（1 年/3 年、No Upfront） |
| `get_reserved_instance_recommendations` | Cost Explorer | RI の購入推奨（EC2/RDS/ElastiCache/Redshift） |
| `get_cost_optimization_hub_recommendations` | Cost Optimization Hub | 統合最適化推奨（Rightsize/Stop/Upgrade/SP） |
| `get_trusted_advisor_cost_checks` | Trusted Advisor | コスト最適化カテゴリのチェック + フラグ付きリソース |

すべてのツールは `target_account_id` パラメータによるクロスアカウント照会をサポートします。

## Benchmark: Powerpipe Exit Code 2 の処理

Powerpipe はベンチマークコントロールにアラームがあると **exit code 2** で終了します。これは正常な動作ですが、従来のコードは異常終了として処理していました。

| 項目 | Before | After |
|------|--------|-------|
| 判定基準 | exit code === 0 | **出力ファイルの存在 + サイズ > 0** |
| exit code 2 | エラー処理 | **正常処理** |

```bash
# exit code は無視し、出力ファイルの有効性で判断
powerpipe benchmark run ... > "${tmpFile}" 2>"${errorFile}"; \
if [ -s "${tmpFile}" ]; then
  mv "${tmpFile}" "${resultFile}" && echo "done" > "${statusFile}";
else
  echo "error" > "${statusFile}";
fi
```

## インフラ: S3 レポートアップロード + update-infra スクリプト

### S3 ポリシー

CDK スタックに EC2 ロールの S3 権限が追加されました:

```typescript
// infra-cdk/lib/awsops-stack.ts
ec2Role.addToPolicy(new iam.PolicyStatement({
  actions: ['s3:PutObject', 's3:GetObject'],
  resources: [`arn:aws:s3:::awsops-deploy-${this.account}/reports/*`],
}));
```

### update-infra スクリプト

EC2 を置き換えずに CDK スタックを安全に更新する `00-update-infra.sh` スクリプト:

1. **既存スタックのパラメータ読み取り** — CloudFormation から現在の値を保持
2. **CDK コンテキストの復元** — VPC、TGW、ドメインなどをライブインフラから再抽出
3. **cdk diff プレビュー** — EC2 置き換えの有無を警告
4. **デプロイ** — `--no-rollback` で安全にデプロイ
